虽然很多项目已经迁到 Git，但在一些老系统、内网环境或特定交付场景里，SVN 仍然会遇到。这里先只整理最常见的命令。

## 1. 安装 SVN

常见安装方式：

```bash
# Arch Linux
paru -S subversion

# Debian / Ubuntu
sudo apt install subversion

# RHEL / CentOS / Rocky / AlmaLinux
sudo dnf install subversion
```

## 2. 帮助命令

```bash
svn help
svn help <subcommand>
svn --version
```

如果已经忘了某个子命令参数，`svn help commit`、`svn help checkout` 往往是最快的办法。

## 3. 检出代码

```bash
svn checkout https://url:port/path/to/repo --username user_name
```

常见缩写：

```bash
svn co https://url:port/path/to/repo --username user_name
```

## 4. 提交代码

### 添加到版本控制

```bash
svn add path/to/file
```

### 提交到远程仓库

```bash
svn commit -m "commit message" path/to/file
```

常见缩写：

```bash
svn ci -m "commit message" path/to/file
```

## 5. 更新代码

```bash
svn update
svn update -r 版本号 path/to/file
```

常见缩写：

```bash
svn up
```

## 6. 使用建议

1. 提交前先用 `svn status` 看当前改动。
2. 如果目录很大，不要习惯性对 `./*` 操作，尽量指定目标路径。
3. 如果后续要把 SVN 服务部署在 Linux 服务器上，可以结合 Docker 专题中的 [8.SVN 仓库服务部署](../Docker%20使用说明与部署/8.SVN%20仓库服务部署.md) 一起看。
