很多后台程序在手动执行时能跑，一重启机器就没了。最常见的解决办法，就是把它交给 systemd 管理。

## 1. 一个最小服务文件

例如把 `frpc` 注册成系统服务，可以在下面目录创建服务文件：

```text
/etc/systemd/system/frpc.service
```

示例内容：

```ini
[Unit]
Description=frpc
After=network.target

[Service]
Type=simple
Restart=always
ExecStart=/usr/local/bin/frpc -c /etc/frpc/frpc.ini

[Install]
WantedBy=multi-user.target
```

## 2. 常见操作

创建或修改服务文件后，通常按下面顺序处理：

```bash
sudo systemctl daemon-reload
sudo systemctl start frpc
sudo systemctl enable frpc
sudo systemctl status frpc
```

常用命令说明：

1. `daemon-reload`：重新加载 unit 文件。
2. `start`：立即启动服务。
3. `stop`：停止服务。
4. `restart`：重启服务。
5. `enable`：设置开机自启。
6. `disable`：取消开机自启。
7. `status`：查看状态。
8. `journalctl -u <service>`：查看服务日志。

## 3. 示例适合解决什么问题

这种写法特别适合下面这类后台任务：

1. 开机后需要自动运行。
2. 进程意外退出后需要自动拉起。
3. 希望通过统一命令查看状态和日志。

## 4. 排查顺序

如果服务起不来，常见排查顺序如下：

1. `systemctl status service-name`
2. `journalctl -u service-name -n 100`
3. 检查 `ExecStart` 路径是否正确。
4. 检查配置文件、工作目录和运行用户权限。

## 5. 使用建议

1. 只修改 unit 文件不够，别忘了执行 `daemon-reload`。
2. 服务依赖网络时，至少加上 `After=network.target` 这类依赖声明。
3. 如果服务访问文件失败，通常还要回头看 [3.文件权限管理](./3.文件权限管理.md) 和 [4.用户指令](./4.用户指令.md)。
