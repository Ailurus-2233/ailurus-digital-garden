语法高亮的问题，通常不只是“有没有颜色”，更常见的是终端能力、文件类型识别、主题设置以及大文件性能之间的组合问题。

## 为什么没有高亮

常见原因通常有三类：

1. 终端本身的颜色能力不够。
2. 文件类型没有被正确识别。
3. 主题或高亮配置没有生效。

## 先确认文件类型

最先应该确认的是当前文件是否识别出了 `filetype`：

```vim
:set filetype?
```

如果没有识别出来，可以临时指定：

```vim
:set filetype=xxx
```

有些脚本文件也会在文件头显式写明希望使用哪种语法：

```text
# vim: syntax=make
```

## 终端颜色设置

在现代终端里，Neovim 更常见的做法是开启真彩色：

```vim
:set termguicolors
```

如果你在非常传统的终端环境里，才需要回头检查 `TERM` 是否配置正确。

## 背景与主题

```vim
:set background=dark
:set background=light
:colorscheme evening
```

如果切换背景或主题后显示异常，可以尝试重置语法：

```vim
:syntax reset
```

## 自定义配色方案

可以把主题文件放到自己的配置目录：

```bash
mkdir -p ~/.config/nvim/colors
cp "$VIMRUNTIME/colors/morning.vim" ~/.config/nvim/colors/mine.vim
```

然后在 Neovim 中启用：

```vim
:colorscheme mine
```

## 关闭高亮

当文件太大、渲染明显变慢时，可以临时或长期关闭语法高亮：

```vim
:syntax clear
:syntax off
```

其中：

1. `:syntax clear` 更偏当前会话级清理。
2. `:syntax off` 更偏明确关闭语法系统。

## 颜色显示异常时的排查顺序

1. 先看 `:set filetype?` 是否正确。
2. 再看当前主题是否可用。
3. 再确认终端和 `termguicolors` 是否匹配。
4. 最后才去怀疑是不是某个插件覆盖了高亮配置。---
