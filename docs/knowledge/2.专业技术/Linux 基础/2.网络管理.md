不同发行版的网络配置方式差异很大。真正要先判断的，不是“配置文件怎么写”，而是“当前系统到底由谁接管网络”。

## 1. 先判断系统正在用什么方案

常见方案包括：

1. `systemd-networkd`
2. 传统 `networking`
3. `netplan`

可以先通过服务状态和配置目录做判断：

```bash
systemctl status systemd-networkd
systemctl status networking
ls /etc/netplan
```

## 2. systemd-networkd

`systemd-networkd` 是 systemd 提供的网络配置守护进程，适合服务器环境，尤其适合不依赖桌面网络管理器的场景。

常见前置条件：

1. `systemd-networkd.service` 已启用。
2. `systemd-resolved.service` 按需启用，用来处理 DNS。

配置文件通常放在：

```text
/etc/systemd/network/*.network
```

### DHCP 示例

```ini
[Match]
Name=enp1s0

[Network]
DHCP=ipv4
```

### 静态 IP 示例

```ini
[Match]
Name=enp1s0

[Network]
Address=10.1.10.9/24
Gateway=10.1.10.1
DNS=10.1.10.1
```

### 无线适配器说明

`systemd-networkd` 本身不负责完成无线认证，通常还需要配合 `wpa_supplicant` 或 `iwd` 之类的工具。

## 3. networking

一些较老的 Debian 系发行版会通过 `networking.service` 和 `/etc/network/interfaces` 管理网络。

例如：

```text
auto enp10s0
iface enp10s0 inet static
    address 192.168.1.162
    netmask 255.255.255.0
    gateway 192.168.1.100
    dns-nameservers 1.0.0.1 1.1.1.1
```

修改完成后，通常需要重启服务：

```bash
sudo systemctl restart networking
```

## 4. netplan

较新的 Ubuntu 等系统经常使用 `netplan`，配置文件通常放在：

```text
/etc/netplan/*.yaml
```

### 静态 IP 示例

```yaml
network:
  version: 2
  renderer: networkd
  ethernets:
    ens5:
      dhcp4: no
      addresses:
        - 192.168.1.230/24
      gateway4: 192.168.1.254
      nameservers:
        addresses:
          - 8.8.4.4
          - 8.8.8.8
```

应用前建议先测试：

```bash
sudo netplan try
sudo netplan apply
```

## 5. 排查顺序

1. 先判断当前系统到底使用哪套网络管理方案。
2. 再确认网卡真实名称，不要直接照抄 `enp1s0`、`ens5` 这类示例名。
3. 改完配置后，优先做测试或语法校验，再正式应用。
4. 如果是远程服务器，修改网络前先确保自己有回退手段。

## 6. 使用建议

1. 尽量不要在一台机器上混用多套网络管理工具。
2. 远程修改网络配置时，优先使用 `netplan try` 或分步重载，降低断联风险。
3. 如果后续还涉及 SSH 远程登录，建议结合 [1.服务器 SSH 配置](./1.服务器%20SSH%20配置.md) 一起看。
