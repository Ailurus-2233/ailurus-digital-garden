开始看 C-ECHO、C-FIND 这些命令之前，最好先把 DICOM 通讯里的几个基本概念对齐。很多排查问题，最后都不是代码写错，而是通信双方的角色、地址、AE Title 或服务对象没有对上。

## 1. DICOM 通讯到底在做什么

从工程视角看，DICOM 通讯可以理解为一套面向医学影像系统的应用层协议。它负责让不同设备或系统之间交换两类内容：

1. 影像和结构化数据。
2. 查询、验证、检索、存储这类操作请求。

在 PACS 场景里，最常见的通信动作通常包括：

1. 用 C-ECHO 验证链路是否可用。
2. 用 C-FIND 查询患者、检查、序列或实例信息。
3. 用 C-MOVE 请求 PACS 把影像发送到指定接收端。
4. 用 C-STORE 上传影像，或接收 PACS 推送的影像。

## 2. 一次通信至少要对齐哪些信息

无论用什么库，至少都要先明确下面几项：

1. 对端 IP 或主机名。
2. 对端监听端口。
3. 本地 Calling AE Title。
4. 远端 Called AE Title。
5. 本地和远端分别承担什么角色。

只要这几项里有一项不一致，就很容易出现“端口能通，但服务请求失败”的情况。

## 3. 通讯排查的正确顺序

比较稳妥的排查顺序通常是：

1. 先确认网络是否可达，例如主机可连、端口开放。
2. 再确认 AE Title 是否配置一致。
3. 先跑 [6.C-ECHO](./6.C-ECHO.md) 验证基本通信。
4. 再跑 [7.C-FIND](./7.C-FIND.md) 验证查询语义。
5. 最后再处理 [8.C-MOVE](./8.C-MOVE.md) 和 [9.C-STORE](./9.C-STORE.md) 这类多角色协作场景。
